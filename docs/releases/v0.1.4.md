## Fix / 修复

Fix repeated startup failure on older Docker:

```text
API version 1.43 is not supported by this client: the minimum supported API version is 1.44
```

luna-ebpf now reads the daemon's actual API version and selects a version
within the exporter's supported range, starting at **API 1.41 / Docker 20.10**.
It does not advertise a newer server API or require upgrading Docker to 25.
Metrics, labels and cgroup backends remain compatible with v0.1.3.

## Install / 安装

Download the Docker archive and `docker-compose.yaml` from this release:

```sh
docker load -i luna-ebpf_0.1.4_docker_amd64.tar.gz
docker compose up -d
curl -fsS http://127.0.0.1:9808/metrics
```

Public image tag: `luna-ebpf:0.1.4`. Verify downloads with `SHA256SUMS`.
Binary archives are provided for Linux amd64 and arm64; the Docker archive
is amd64 only. Existing source installations can rebuild with `docker compose up --build -d`.

## Validation / 验证

Strict HTTP tests cover API 1.41, 1.42, 1.43, 1.44, 1.52 and a newer daemon
API capped to the SDK maximum. Tests include list/inspect, version/info,
events, malformed/unsupported responses, cancellation and HEAD-to-GET fallback.

Real isolated Docker daemons validate independent TCP/UDP RX/TX counters,
idle isolation, rename, container restart/retirement and daemon recovery.
The old v0.1.3 binary reproduces the original error against the real old
daemon; the new binary passes. See `docs/validation.md` for exact versions
and backend scope. Unit/race/vet, BPF generation and cross-builds are checked.

## Limits / 限制

API compatibility does not remove kernel requirements. cgroup v1 still
requires readable kernel BTF and supported probes. API versions below 1.41
are unsupported. arm64 runtime and production-scale high-PPS operation remain
unverified. Agent restarts reset cumulative counters; Prometheus `rate()`
handles counter resets. No private registry or host evidence is published.

Full changes: https://github.com/AllenxuX/luna-ebpf/compare/v0.1.3...v0.1.4
